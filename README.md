# Rooster POS · 备菜原型

打开 `index.html`，默认进入“1. 第三方系统绑定”预览；左侧依次提供第三方系统绑定、备菜配方设置与备菜功能，并可查看产品说明、功能清单和视频解说。

预览壳与运行版 Demo 均固定为 1280 × 800 的平板设计比例；当可用空间不足时会等比缩小显示，避免出现滚动条。

需求目的：满足 tigawok 自选快餐场景，支持餐厅在售卖前提前备菜、完成出餐，顾客再自选菜品销售；同时打通 Next Robot 机器人炒菜系统，支撑标准化批次备菜与可售库存管理。

当前原型的应用端为 POS，包含三个主功能及对应的可运行 Demo：第三方系统绑定、备菜配方设置、备菜功能。日常备菜以卡片显示每个菜品的今日已售和当前可售数；员工选择批次并统一送厨。送厨成功后，系统立即按固定“每批可售份数”增加关联销售菜单品的 Count，不展示或追踪下游厨房的制作、出餐状态。原型不包含模拟结账、厨房完成或回传状态。

预制配方需要预先配置：名称、关联销售菜单品、固定批次单位、每批可售份数，以及 KDS 工位、厨房打印机、Next Robot 等送厨渠道。备菜配方列表支持按名称搜索、勾选全选、批量删除与单项编辑。Next Robot 在“第三方应用集成 → 厨房系统”使用 App ID 与 Secret 绑定成功后显示；随后通过独立的“同步菜品”按钮获取可用设备和 Robot 菜品。正常路径不录入实际产出；异常情况应使用独立的异常调整机制。

`demo/assets/rooster-home-reference.png` 与 `demo/assets/pos-order-reference.png` 为用户提供的 Rooster 首页、点餐页原始截图，Demo 直接复用为视觉底稿；其余页面为 Rooster 风格的备菜交互演示。

`assets/nextrobot.mp4` 为「视频解说」页面内嵌播放的视频文件，已复制至原型目录，不依赖外部路径。
